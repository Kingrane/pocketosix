# Участие в PocketOSix

Спасибо за интерес к проекту. Мы поддерживаем настоящую гостевую Linux-среду, небольшую понятную веб-оболочку и честную документацию ограничений. До работы прочитайте [README.md](README.md) и [AGENTS.md](AGENTS.md).

## Подготовка окружения

Нужны Node.js ≥ 20.9 (рекомендуется 24), npm и desktop Chrome / Edge. В каталоге репозитория:

```powershell
npm install
npm run dev
```

Приложение открывается на `http://localhost:3000`; dev использует webpack. Лендинг и `/docs` не загружают CheerpX. Для настоящего boot откройте `/run` и нажмите `> boot`: начнётся загрузка runtime и базового диска по сети. Tailscale для GUI не нужен.

Для browser tests:

```powershell
npx playwright install chromium
```

Не помещайте приватные credentials в `.env` или test fixtures. Все `NEXT_PUBLIC_*` видны пользователям сборки. Если меняете образ, задайте новый `NEXT_PUBLIC_DISK_ID` вместе с его URL и backend; не переиспользуйте существующий overlay.

## Как предложить изменение

1. Для архитектурных изменений, нового образа, обновления SDK и изменения хранения сначала опишите задачу и риски в issue.
2. Сделайте отдельную ветку с небольшим изменением. Не включайте несвязанный рефакторинг или форматирование всего репозитория.
3. Добавьте или обновите проверки, соответствующие изменению. Для исправления бага предпочтителен тест, воспроизводящий его.
4. Обновите документацию, если меняются поведение, команды, конфигурация или границы поддержки.
5. В pull request опишите цель, реализацию, риски для пользовательского диска и фактические результаты проверок. Для UI добавьте скриншоты без приватных данных.

Не заменяйте настоящий runtime mock-версией ради успешного demo. Изолированные test doubles допустимы в детерминированных тестах, но не в production и не как доказательство работающего Linux.

## Проверки перед pull request

```powershell
npm run typecheck
npm run lint
npm test
npm run build
npm run test:e2e
```

При изменении SDK-интеграции, загрузки или диска отдельно выполните opt-in проверку:

```powershell
npm run test:vm
```

Она использует настоящий runtime, требует сеть и может расходовать заметные CPU / RAM. Изучите текущие assertions в `tests/`: наличие команды не гарантирует проверку всех сценариев ниже. Если проверка недоступна, явно укажите причину; не выдавайте skipped / timeout за passed. Не меняйте адаптер VM во время прогона на dev-сервере: его HMR намеренно перезагружает документ. Для стабильного прогона можно предварительно запустить production-сервер через `npm run build` / `npm start`.

Ручные сценарии для изменений соответствующих частей:

- Реальный boot Xorg / i3, открытие терминала и доставка keyboard / mouse input без дублирования.
- Запись тестового файла на root disk, reload и повторное чтение; отсутствие обещаний сохранения RAM.
- Вторая вкладка того же origin не получает право параллельной записи; после закрытия владельца возможен безопасный повторный запуск.
- React StrictMode / повторный mount не создают второй boot, зависшие locks и callbacks.
- Ошибка сети / CDN отображается честно и не вызывает автоматического reset.
- Запрос persistent storage корректно показывает результат, включая отказ.
- Reset требует подтверждение, затрагивает только свой диск и корректно обрабатывает открытые подключения.
- Кнопки, keyboard focus и диалоги доступны; при активном диалоге ввод не уходит в гостя.
- COOP / COEP есть в реальном ответе сервера; production origin действительно cross-origin isolated.

**Разрушающие проверки проводите только в отдельном тестовом profile / origin и на диске, данные которого не жалко потерять.** Не запускайте reset на своем рабочем диске или данных другого человека. Не используйте очистку всех данных сайта как обычный шаг тестирования.

## Переводы — translations welcome

Интерфейс по умолчанию — English, без определения языка браузера. Выбор хранится в cookie `pocketosix-locale`; переключатель общий для лендинга, справки и рабочего стола. Тексты находятся в `messages/en.json` и `messages/ru.json`, обращение из компонентов — `t("section.key")`.

Чтобы добавить язык, скопируйте `messages/en.json` в новый JSON-файл, переведите значения (сохранив все ключи) и добавьте одну строку с кодом и названием языка в `languages` в `lib/i18n.ts`. Импорт словаря автоматический. Запустите `npm test`: проверка сравнивает ключи и непустые строки всех настроенных языков. Technical terms и сочетания клавиш оставляйте без изменений. Русский текст — нейтральный, без обращения на «ты». Новые переводы приветствуются; Chinese сейчас не добавляется.

## Сообщение о проблеме

Укажите:

- ОС, версию браузера и Node.js, revision проекта и deployment type;
- origin (без секретных query / fragment), версию base image и ID overlay;
- шаги воспроизведения, ожидаемое и фактическое поведение;
- статус `crossOriginIsolated`, сообщения ошибок и необходимые логи;
- была ли открыта другая вкладка, менялся ли base, использовался ли приватный режим;
- для сети — факт подключения Tailscale / exit node, без auth keys и персональных сетевых данных;
- команды проверок и их действительный результат.

Удаляйте credentials, личные файлы, tailnet-адреса и другие чувствительные данные из публичных логов. Не публикуйте уязвимости, позволяющие получить чужие данные или секреты, вместе с такими данными: сначала согласуйте приватный канал с сопровождающими.
