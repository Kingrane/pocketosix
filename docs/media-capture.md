# Настоящее медиа для продукта

[README](../README.ru.md) · [Разработка и opt-in capture](development.md)

Это **план будущей съёмки**, не утверждение, что видео и все карточки уже созданы или проверены. Публикуются реальные кадры гостя / браузера, без нарисованного терминала, вставленного canned output, подмены приложений или фальшивых графиков. Новые публичные изображения здесь не генерируются.

## Общие правила

- Отдельный **test profile / origin**, не пользовательский диск. Не сбрасывайте личное хранилище ради capture.
- Реальный CheerpX с официального CDN, неизменный base / overlay pairing; GUI запускается обычным явным `> boot`.
- Дождитесь приглашения shell и результата команды, а не одного boot-лога / canvas. Наличие окна не доказывает готовый второй терминал.
- Скрыть браузерные настройки, логи, приватные файлы, аккаунты, токены, Tailscale IP / tailnet и сетевые панели. Tailscale для кадров не нужен.
- Пользовательские обои можно включать: владелец подтвердил право распространения. Они не становятся MIT; сохранить [notices](../THIRD_PARTY_NOTICES.md).
- Записать provenance: дата, browser / version, тестовый origin, размер framebuffer, реальные команды, результат, какие сценарии **не** проверялись. Сохранить исходник без ретуши рядом с отчётом, не публикуя приватные метаданные.

## Hero

Файлы для лендинга:

```text
public/hero-desktop.webm
public/hero-desktop.mp4
public/hero-desktop.png
```

1. Захватить **настоящий guest framebuffer 1920×1200**. Короткий спокойный цикл: живой терминал, реальная команда, небольшое перемещение / изменение размера настоящего окна; без ускоренного «мгновенного boot» и симуляции ввода. Не объявлять работоспособность всех приложений по этому кадру.
2. Оставить читаемые реальные `uname -a` и `cat /etc/alpine-release`; `uname` внутри CheerpX **не доказывает наличие настоящего kernel**. `neofetch` не обязателен: в предыдущем образе он отсутствовал.
3. Экспортировать **WebM и MP4 без аудиодорожки**, с одинаковым коротким loop и итоговым суммарным размером видео **меньше 3 MB**. Если размер / читаемость не достигаются, укоротить сцену или оставить проверенный poster, а не ухудшать достоверность кадра.
4. Poster PNG — реальный кадр того же захвата, **1920×1200**, без дорисовки окон или текста. Можно дополнительно подготовить WebP для доставки, сохранив оригинал и provenance.
5. Доставлять muted / loop / playsinline, лениво; autoplay только когда кадр видим и motion разрешён. При offscreen, скрытой вкладке и `prefers-reduced-motion` видео должно останавливаться, при reduced motion показывается poster. Это требование к UI, не функция launcher.

Существующий REDESIGN2 poster — прежний проверенный framebuffer с `uname -a`, Alpine release и **вторым пустым** xterm. Его shell не подтверждена. Новый capture не должен автоматически заменять этот файл без проверки. [Исторический provenance](../artifacts/redesign2/hero-provenance.json).

## Карточка Shell

**`public/feature-shell.png`**, композиция **16:10** (предпочтительно 1920×1200): настоящий xterm в госте, читаемые команда и результат:

```sh
uname -a
cat /etc/alpine-release
pwd
```

Команды выполняются **в Linux-госте, не PowerShell**. Кадр должен показать реальное приглашение shell и выполненный вывод, не boot-экран / echo введённого текста. Не добавляйте вывод отсутствующего `neofetch`, логотип distro поверх терминала или claim настоящего Linux kernel. Дополнительный терминал нужен только если в нём действительно подтверждены prompt и исполнение.

## Карточка Disk

**`public/feature-disk.png`**, **16:10**: настоящий терминал или файловый менеджер с **фактически созданным тестовым файлом** в домашнем каталоге отдельного тестового профиля. Например, в гостевом терминале:

```sh
printf 'pocketosix capture sample\n' > "$HOME/pocketosix-capture.txt"
cat "$HOME/pocketosix-capture.txt"
```

Выполняйте создание только в выбранном test disk, где имя не занято важным файлом. Не показывайте чужой home, private файлы или фиктивный «Saved» badge. Один `cat` доказывает чтение текущей сессии, **не сохранность после reload**.

Если текст карточки говорит о persistence, отдельно дождитесь реально наблюдаемого IDB commit тестового маркера, выполните reload и явный boot на **том же origin / profile**, затем подтвердите чтение файла из гостя. Запишите результат до публикации. `sync`, пауза на фиксированное число секунд, storage quota или отсутствие ошибок не доказывают durable commit всех очередей. Если reload-проверка не прошла / не выполнена, не используйте media как доказательство сохранения. Reset, если нужен для теста, только подтверждённый и только в тестовом профиле.

## Карточка Local

**`public/feature-local.png`**, **16:10**: реальный guest canvas рядом с настоящей записью **DevTools Performance** браузера (WASM / worker activity), либо документированная браузерная диагностика работающего runtime. Используйте отдельный clean capture profile; не показывайте private URLs, профили, имена файлов или содержимое памяти.

Захват должен соответствовать реальному действию в госте; сохранить оригинальный trace и точный источник диаграммы. Запись проверяет наблюдаемую браузерную активность, а не универсальный performance benchmark. Если браузер не показывает нужную WASM / worker детализацию, выберите другой честный диагностический кадр или обычный живой guest screen и явно опишите ограничение. **Нельзя** дорисовывать CPU-линии, counters, «100% local» charts или API-данные, которых не было.

Локальный compute не отменяет runtime / disk CDN и Tailscale. Не заявляйте «0 внешних серверов», standalone download или offline по этому изображению. Если измерение cold boot / base size ещё не выполнено, числам место в отчёте после замера, не в фальшивом capture.

## Перед публикацией

Проверить реальные окна, prompt / вывод, размер и вес файлов, loop, poster, reduced motion / offscreen-паузу и отсутствие приватных данных. Медиа не заменяет проверки ввода, committed persistence, second-writer lock, reset или сети. Незаполненный слот / проверенный прежний poster предпочтительнее выдуманного результата. В отчёте указать, что действительно снято и какие проверки пропущены.
