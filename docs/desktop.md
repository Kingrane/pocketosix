# Локальный desktop и плавающие окна i3

[English README](../README.md) · [Русский README](../README.ru.md)

## Без лендинга

Из корня установленного проекта:

```powershell
npm run desktop
```

Launcher использует `process.execPath` и установленный `next/dist/bin/next`: `next dev --webpack --port 3000`. Нового runtime, backend Linux, автоавторизации или автоматического изменения гостя нет. По сообщению Next `Ready` выполняется HTTP GET к **http://localhost:3000/run**; браузер открывается только после ответа **200**. Затем пользователь сам нажимает **`> boot`**. Готовность Next не означает готовность Linux, Xorg или shell.

Ожидание запуска сервера и ответа `/run` ограничено **120 секундами**. Ошибка HTTP, timeout или завершение Next не считаются успешным запуском; браузер не открывается. При такой ошибке launcher останавливает свой дочерний процесс. Если системная команда открытия браузера недоступна, сервер остаётся работающим, а в терминале выводится адрес для ручного открытия. Windows использует `cmd.exe /c start`, macOS — `open`, Linux — `xdg-open`.

Порт **3000 фиксирован**: Next получает явный `--port`, который отключает retry на другом порту. Launcher не переиспользует уже работающий сервер и не останавливает чужие процессы. Если порт занят, откройте `/run` на своём уже запущенном сервере вручную либо сначала остановите именно его. Не меняйте порт «для удобства»: для IndexedDB это другой origin и отдельный диск. **Ctrl+C** передаёт `SIGINT` только дочернему Next-процессу launcher; поведение завершения дерева процессов зависит от ОС и Next CLI.

Обычный путь также остаётся доступным:

```powershell
npm run dev
```

Далее откройте `/run` вручную. Это рабочая область; `/` — лендинг, `/docs` — справка без SDK. Production-сборка и проверки описаны в [development.md](development.md).

## Ярлык приложения в браузере

Можно создать обычный ярлык браузера на постоянный адрес `/run` или использовать встроенное действие браузера «открывать как приложение», если оно доступно. Локальный сервер при этом должен работать. Это только отдельное окно браузера: не новая самостоятельная ОС, не установщик Linux и не обещание offline. Изменять PWA или добавлять service worker для этого не требуется.

Runtime загружается с официального CDN, базовый диск — блоками с `disks.webvm.io`; writable overlay не равен полному скачанному образу. RAM и процессы после закрытия / reload не восстанавливаются. [Подробнее о локальном диске](storage-network.md).

## Управление на `/run`

- **Docked** — слева rail шириной **48 px**; одновременно открыта только одна панель **320 px**. На desktop панель сдвигает canvas, на узком экране (до 720 px) накладывается поверх него. Повторное нажатие активной кнопки закрывает панель.
- **Immersive** — HTML fullscreen всего документа, не fullscreen отдельного окна i3. Rail скрыт; notch вверху показывает pill при наведении / нажатии или движении мыши к верхней границе. Pill расположен **от 60 px сверху**, с учётом safe area, ниже стандартной панели i3; без наведения, фокуса и открытой панели / диалога скрывается через **2 секунды**. Кнопка выхода возвращает Docked.
- В обоих режимах доступны **те же панели**: Display, Terminal, Disk, Network, Shortcuts, Logs. В Immersive они открываются справа поверх canvas.
- **Ctrl + Alt + Shift + M** открывает меню, в том числе при фокусе в госте, **после отпускания всех клавиш**: реальные keyup модификаторов сначала получает SDK, без синтетической пересылки. **Ctrl + K** открывает палитру только из браузерных элементов управления; в гостевом canvas / KMS-вводе и **tty1** сочетание не перехватывается. M / K — физические клавиши, независимо от раскладки.
- **Escape при фокусе в госте принадлежит гостю**, не вызывает выход из PocketOSix. Браузер может использовать его для выхода из fullscreen; в браузерной панели он может закрыть панель. Диалог выхода не закрывается через Escape.
- **Exit to home** (логотип) / **Back to home** открывает подтверждение **Leave / Stay**. Stay оставляет сессию; Leave выполняет полную навигацию документа на `/`, завершая старый runtime / writers и процессы, **без reset диска**. Сохраняются уже committed изменения, но не гарантируются pending-записи, RAM или работающие сессии.

Немодальная desktop Docked-панель сама по себе не блокирует tty1-ввод или восстановление KMS-фокуса: `sendTerminal` и `useKmsInput` учитывают именно **`dialog:modal`**, а не любое `dialog[open]`. Когда панель превращается в мобильный overlay, фокус переходит в панель; `useKmsInput` не возвращает его в canvas внутри **inert**-области. Это уточнение UI-фокуса, не изменение boot, диска или сети.

## Терминал

Дождитесь настоящей гостевой панели и используйте **Apps → Terminal**; вводите команды только после появления shell prompt. `Alt + Enter` есть в upstream-конфиге, но в предыдущих реальных прогонах запуск этим сочетанием не подтвердился. Рисунок canvas и boot-лог сами по себе не доказывают готовность shell или второго терминала.

Отдельная консоль оболочки подключена к настоящей **tty1**, а не имитирует shell. В стандартном образе заводские данные: `user` / `password`, если вы их не меняли. Это публичные данные образа, не секрет приложения. tty1 имеет фиксированный размер **100×30**: подтверждённого официального API resize PTY в SDK 1.4.0 нет. Успешный login tty1 не доказывает готовность Xorg; ввод в tty1 при активном GUI требует отдельной проверки.

## Оставить i3, включить floating вручную

Рекомендуемый первый шаг — **не менять образ или оконный менеджер**. i3 уже умеет плавающие окна. Ни инструкция, ни launcher не выполняют эти изменения автоматически и не вызывают SDK `run()` для настройки гостя.

Сверено с [официальным руководством i3](https://i3wm.org/docs/userguide.html#_floating) и [upstream-конфигом, commit `810dc414`](https://github.com/leaningtech/alpine-image/blob/810dc414a8abfb3e21bf57b10651474baab39cdf/config/i3/config). [Dockerfile того же commit](https://github.com/leaningtech/alpine-image/blob/810dc414a8abfb3e21bf57b10651474baab39cdf/Dockerfile) копирует конфиг в **`/home/user/.config/i3/config`**. Это проверка исходников, не новая проверка всех приложений в работающем госте. Ваш overlay мог уже изменить настройки; приоритет имеет фактически загруженный конфиг.

**Следующие команды — в терминале Linux внутри гостевого GUI, не в PowerShell.** Используйте терминал пользователя той же Xorg/i3-сессии, обычно `user`, а не root из другой tty.

1. Проверьте пользователя, домашний каталог и загруженный конфиг:

   ```sh
   whoami
   printf '%s\n' "$HOME"
   i3 --moreversion
   ```

   Ожидаемый upstream-путь — `/home/user/.config/i3/config`. i3 также поддерживает `~/.i3/config` и системный `/etc/i3/config`; не создавайте конкурирующий конфиг вслепую. Если загружен другой файл, используйте его фактический путь. Если main config системный, сначала разберитесь, как текущая сессия выбирает пользовательский конфиг; шаги ниже относятся к уже существующему пользовательскому файлу.

2. Для подтверждённого `~/.config/i3/config` сделайте резервную копию и запишите её имя:

   ```sh
   cfg="$HOME/.config/i3/config"
   backup="${cfg}.before-floating.$(date +%Y%m%d-%H%M%S)"
   cp -p "$cfg" "$backup"
   printf 'Backup: %s\n' "$backup"
   vi "$cfg"
   ```

3. Сохраните существующий `set $mod Mod1` (**Alt**, не Super / Windows). Вне блоков `mode` и других вложенных блоков добавьте правило для новых окон:

   ```i3
   for_window [class=".*"] floating enable
   ```

   Убедитесь, что уже существующая строка имеет вид `floating_modifier $mod`; в upstream она есть, повторно добавлять её не нужно. Правило относится к окнам с соответствующим X11 class; оно не гарантирует одинаковое поведение всех приложений, панелей и диалогов.

4. Проверьте синтаксис и перечитайте настройки из того же гостевого терминала:

   ```sh
   i3 -C -c "$cfg"
   i3-msg reload
   ```

   Если проверка сообщает ошибку, сначала исправьте её, не выполняйте reload. Новое правило — прежде всего для вновь появляющихся окон. Уже открытое окно переключайте вручную: фокус на нём → **Alt + Shift + Space**. Браузер / ОС могут перехватывать сочетания.

С `floating_modifier $mod`: **Alt + перетаскивание левой кнопкой** перемещает плавающее окно; **Alt + перетаскивание правой кнопкой** меняет размер. Можно также тянуть заголовок и границы окна. Полноэкранное окно i3 сначала верните через **Alt + F** — это не fullscreen браузера.

### Вернуть tiling

Удалите добавленное `for_window` или восстановите записанную резервную копию. В том же терминале, если переменные ещё определены:

```sh
cp -p "$backup" "$cfg"
i3 -C -c "$cfg"
i3-msg reload
```

После новой терминальной сессии переменные нужно задать заново по сохранённым путям. Уже плавающие окна возвращаются в tiling через **Alt + Shift + Space**. Сброс всего диска для этой настройки не нужен. Изменения конфигурации записываются в overlay асинхронно; `sync` не является подтверждённой гарантией мгновенного IDB commit.

## Основные сочетания

| Сочетание | Действие в upstream i3 |
| --- | --- |
| `Alt + Enter` / `Alt + D` | Терминал / rofi; доставка браузером не гарантируется |
| `Alt + Shift + Q` | Закрыть активное окно |
| `Alt + стрелки` / `Alt + Shift + стрелки` | Фокус / перемещение окна |
| `Alt + H` / `Alt + V` | Горизонтальное / вертикальное разбиение |
| `Alt + F` | Fullscreen окна i3 |
| `Alt + 1…9`, `Alt + 0` | Рабочие пространства 1…10 |
| `Alt + Shift + 1…9`, `Alt + Shift + 0` | Перенос окна на пространство |
| `Alt + Shift + Space` | Floating / tiling |
| `Alt + R` | Resize mode; `Enter` / `Escape` — выход |
| `Alt + Shift + C` | Перечитать конфиг |

Сначала щёлкните по гостевому экрану. Используйте фактические bindings своего диска, если конфиг менялся. Ввод KMS обслуживает SDK; эти инструкции не добавляют synthetic keyboard / mouse или гарантированную вставку браузерного clipboard.

## Если нужен именно Openbox

Полная замена WM на Openbox — отдельная задача для совместимого custom image, а не изменение здесь. Новый base требует **нового `NEXT_PUBLIC_DISK_ID`**, даже если URL образа остался прежним; старый overlay повторно открывать на другом base нельзя. Потребуются проверка Xorg / пакетов / ввода и их лицензий, а также соблюдение proprietary-условий CheerpX. Автоматической миграции диска и подтверждённой совместимости Openbox здесь нет.
