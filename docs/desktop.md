# Локальный desktop и плавающие окна i3

[English README](../README.md) · [Русский README](../README.ru.md)

## Без лендинга

Из корня установленного проекта:

```powershell
npm run desktop
```

Launcher использует `process.execPath` и установленный `next/dist/bin/next`: `next dev --webpack --port 3000`. Нового runtime, backend Linux, автоавторизации или автоматического изменения гостя нет. По сообщению Next `Ready` выполняется HTTP GET к **http://localhost:3000/run**; браузер открывается только после ответа **200**. Затем пользователь сам нажимает **`> boot`**. Готовность Next не означает готовность Linux, Xorg или shell.

Ожидание запуска сервера и ответа `/run` ограничено **120 секундами**. Ошибка HTTP, timeout или завершение Next не считаются успешным запуском; браузер не открывается. При такой ошибке launcher останавливает свой дочерний процесс. Если системная команда открытия браузера недоступна, сервер остаётся работающим, а в терминале выводится адрес для ручного открытия. Windows использует `cmd.exe /c start`, macOS — `open`, Linux — `xdg-open`.

Порт **3000 фиксирован**: Next получает явный `--port`, который отключает retry на другом порту. Launcher не переиспользует уже работающий сервер и не останавливает чужие процессы. Если порт занят, откройте `/run` на своём уже запущенном сервере вручную либо сначала остановите именно его. Не меняйте порт «для удобства»: для IndexedDB это другой origin и отдельный диск. **Ctrl+C** передаёт `SIGINT` только дочернему Next-процессу launcher; поведение завершения дерева процессов зависит от ОС и Next CLI.

Обычный путь также остаётся доступным:

```powershell
npm run dev
```

Далее откройте `/run` вручную. Это рабочая область; `/` — лендинг, `/docs` — справка без SDK. Production-сборка и проверки описаны в [development.md](development.md).

## Ярлык приложения в браузере

Можно создать обычный ярлык браузера на постоянный адрес `/run` или использовать встроенное действие браузера «открывать как приложение», если оно доступно. Локальный сервер при этом должен работать. Это только отдельное окно браузера: не новая самостоятельная ОС, не установщик Linux и не обещание offline. Изменять PWA или добавлять service worker для этого не требуется.

Runtime загружается с официального CDN, базовый диск — блоками с `disks.webvm.io`; writable overlay не равен полному скачанному образу. RAM и процессы после закрытия / reload не восстанавливаются. [Подробнее о локальном диске](storage-network.md).

При холодном запуске нужны загрузка runtime и получение блоков base; недоступность или блокировка CDN может остановить boot. Это отдельно от отзывчивости браузерных панелей: быстрое открытие меню не доказывает готовность гостя, а задержка запуска Linux сама по себе не доказывает зависание браузерного UI. Фиксированное время boot не обещается.

## Управление на `/run`

- **Docked** — слева rail шириной **48 px**; одновременно открыта только одна панель шириной до **320 px**. Все семь браузерных панелей накладываются поверх рабочей области и не сдвигают / не меняют размер гостевого canvas при открытии и закрытии. Повторное нажатие активной кнопки закрывает панель.
- **Immersive** — HTML fullscreen всего документа, не fullscreen отдельного окна i3. Rail скрыт; notch вверху показывает pill при наведении / нажатии или движении мыши к верхней границе. Pill расположен **от 60 px сверху**, с учётом safe area, ниже стандартной панели i3; без наведения, фокуса и открытой панели / диалога скрывается через **2 секунды**. Кнопка выхода возвращает Docked.
- В обоих режимах доступны **те же семь панелей**: Приложения / Apps, Экран / Display, Терминал / Terminal, Диск / Disk, Сеть / Network, Сочетания клавиш / Shortcuts, Логи / Logs. В Immersive они открываются справа поверх canvas.
- **Ctrl + Alt + Shift + M** открывает меню, в том числе при фокусе в госте, **после отпускания всех клавиш**: реальные keyup модификаторов сначала получает SDK, без синтетической пересылки. **Ctrl + K** открывает палитру только из браузерных элементов управления; в гостевом canvas / KMS-вводе и **tty1** сочетание не перехватывается. M / K — физические клавиши, независимо от раскладки.
- **Escape при фокусе в госте принадлежит гостю**, не вызывает выход из PocketOSix. Браузер может использовать его для выхода из fullscreen; в браузерной панели он может закрыть панель. Диалог выхода не закрывается через Escape.
- **Exit to home** (логотип) / **Back to home** открывает подтверждение **Leave / Stay**. Stay оставляет сессию; Leave выполняет полную навигацию документа на `/`, завершая старый runtime / writers и процессы, **без reset диска**. Сохраняются уже committed изменения, но не гарантируются pending-записи, RAM или работающие сессии.

При открытой браузерной панели или диалоге фокус находится в UI оболочки, а гостевая рабочая область и KMS-ввод заблокированы через **inert**. Чтобы снова управлять гостем, закройте панель и щёлкните по гостевому окну. Это изоляция ввода, не остановка Linux, reset диска или отключение сети.

### Гостевое окно и браузерная панель — не одно и то же

- **Окно приложения внутри canvas** принадлежит Xorg / i3. В гостевом меню **Apps → Terminal** запускается `xterm`, **Apps → Files** — Thunar, **Apps → Launcher** — `rofi -show drun`. Это меню гостя, не новая браузерная панель «Приложения».
- **Приложения, Экран, Терминал, Диск, Сеть, Сочетания клавиш, Логи** — браузерные панели PocketOSix. Кнопка **Close / Закрыть в заголовке панели** убирает только такую панель, не закрывает гостевые приложения и не сбрасывает диск. Кнопки в строках списка «Окна Linux» имеют другую цель — конкретное гостевое окно.
- Чтобы закрыть **гостевое приложение**, используйте кнопку его строки в [панели «Приложения»](#приложения-и-окна-linux). Другой путь: закройте браузерную панель, щёлкните по нужному окну внутри canvas и нажмите **Alt + Shift + Q**. В i3 это команда `kill`, а не выход из PocketOSix. Сохраните работу заранее: [поведение закрытия](https://i3wm.org/docs/userguide.html#_closing_windows) зависит от поддержки приложением протокола `WM_DELETE`; сохранение изменений не гарантируется.
- Отдельная **tty1-консоль** оболочки — не GUI-терминал i3. Её кнопка закрытия скрывает браузерное представление консоли, а не закрывает окно `xterm`. Консоль накладывается снизу / справа; перемещение, изменение размера и разворачивание консоли не меняют геометрию гостевого framebuffer. Разворачивание закрывает гостевой экран и блокирует его ввод, но сохраняет canvas смонтированным.

Настоящее изменение viewport / fullscreen объединяется за **150 мс**. Размер берётся со стабильного stage, округляется до целых CSS pixels и ограничивается **4096 px по каждой оси**, с минимумом **1024×768**. Fit / Native меняют только браузерное отображение; Native позволяет прокрутить исходное изображение. Host cursor скрывается только над активным гостевым canvas: Xorg рисует свой курсор внутри framebuffer. На кнопках оболочки остаётся обычный браузерный указатель.

### Приложения и окна Linux

**Статус новой реализации:** ниже описано поведение текущего кода, а не отчёт об успешной проверке в настоящем госте. Проверки новых кнопок, floating, close / hide / restore и измерения ещё не завершены; ускорение запуска или гарантия совместимости не заявляются.

После boot откройте браузерную панель **Приложения / Apps**. Её открытие запрашивает настоящую текущую i3-сессию и дерево окон. При недоступной / неоднозначной сессии или отсутствии нужных утилит показывается ошибка; действия не заменяются имитацией. Кнопки запуска доступны после проверки гостя и найденного приложения, не во время другого действия.

| Кнопка в панели | Действие в госте |
| --- | --- |
| Все приложения / All applications | `rofi -normal-window -show drun` — launcher как обычное управляемое окно i3 |
| Терминал Linux / Linux terminal | `xterm` — GUI-терминал той же Xorg/i3-сессии |
| Файлы · Thunar / Files · Thunar | Thunar, как в исходном гостевом меню Files |
| Файлы · PCManFM / Files · PCManFM | Отдельный файловый менеджер PCManFM, если найден в текущем госте |

Это настоящие гостевые команды через i3 IPC, не синтетические Alt-сочетания. Браузерная панель закрывается при запуске, чтобы вернуть ввод гостю. Принятие команды i3 не означает появления готового приложения: реализация ожидает подходящее реальное окно в дереве и сообщает ошибку, если оно не найдено за 30 секунд, без автоматического повторного запуска. Наличие окна также не доказывает готовность shell prompt или отзывчивость приложения. `-normal-window` не является обещанием исправить все проблемы ввода rofi. PCManFM — альтернатива Thunar, **не доказанное ускорение**.

**Обновить окна / Refresh windows** перечитывает реальное дерево i3. Список показывает названия, классы и состояние настоящих окон, включая скрытые в scratchpad; это не браузерные копии приложений. Он обновляется при открытии панели и после её действий, но не отслеживает каждое изменение непрерывно. После изменений из самого гостя обновляйте список вручную.

- **Закрыть в строке окна / Close** отправляет `kill` только выбранному окну по проверенным container / window ID. Сохраните документы заранее. Приложение может запросить сохранение или отказать в закрытии; окно не считается исчезнувшим только по принятию команды. Закройте панель, чтобы ответить на настоящий гостевой диалог, затем обновите список.
- **Скрыть окно / Hide window** переносит выбранное окно в **scratchpad i3**. Это скрытие, не стандартная X11-минимизация и не завершение процесса: приложение и несохранённые документы остаются в RAM.
- **Показать окно / Show window** явно показывает выбранное скрытое окно из scratchpad. Для уже видимого окна восстановление не отправляется: `scratchpad show` работает как toggle и мог бы снова скрыть его.

Ни скрытие, ни обновление списка не сохраняют документы на диск. После reload / выхода процессы и несохранённые документы теряются; сохраняются только уже committed изменения диска. Верхняя кнопка «Закрыть» по-прежнему закрывает **панель**, а не перечисленные окна.

### Плавающий режим текущей сессии

В панели **Приложения** нажмите **Включить плавающие окна / Use floating windows**. Режим включается только по вашему действию: уже открытые tiled **обычные окна** и новые обычные окна становятся floating через подписку на события текущего i3. Уже плавающие окна, специальные окна / диалоги и окна scratchpad не переключаются. Пока режим активен, новые подходящие окна из самого гостя также обрабатываются, не только запущенные браузерными кнопками.

Конфиг i3 не переписывается, пакеты не устанавливаются, base и overlay ID не меняются. Режим не сохраняется после завершения / перезапуска сессии или reload страницы и не включается автоматически при следующем boot. Закрытие панели «Приложения» само по себе режим не выключает.

Для плавающего окна тяните заголовок, чтобы переместить его; **Alt + левая кнопка** также перемещает, **Alt + правая кнопка** меняет размер при `floating_modifier $mod`. Это управление внутри гостя, после закрытия браузерной панели и фокуса на canvas. Доставка ввода и drag требуют реальной проверки в вашем браузере / ОС.

**Выключить плавающий режим / Stop floating mode** останавливает подписчик и возвращает в tiling только ещё видимые, ещё плавающие окна, которые он сам переключил. Уже floating до включения окна не затрагиваются; скрытые пользователем scratchpad-окна **никогда не показываются автоматически**, в том числе при выключении режима. Для них используйте явную кнопку «Показать окно».

**Точная прежняя иерархия tiles, порядок и геометрия окон не восстанавливаются.** Это обратное переключение режима выбранных окон, не snapshot раскладки. Ошибка переключения / восстановления показывается отдельно и не означает успешного отката. Сброс диска для выключения режима не нужен.

## Терминал

Для терминала **Linux внутри GUI** используйте **Приложения → Терминал Linux** в браузерной панели либо **Apps → Terminal** в меню гостя. Это `xterm` той же Xorg/i3-сессии; вводите команды только после появления shell prompt. `Alt + Enter` есть в upstream-конфиге, но в предыдущих реальных прогонах запуск этим сочетанием не подтвердился. Рисунок canvas и boot-лог сами по себе не доказывают готовность shell или второго терминала.

Браузерная панель **Терминал / Terminal → Открыть терминал / Open terminal** открывает другое представление: отдельную консоль оболочки, подключённую к настоящей **tty1**, не `xterm` и не имитацию shell. В стандартном образе заводские данные: `user` / `password`, если вы их не меняли. Это публичные данные образа, не секрет приложения. tty1 имеет фиксированный размер **100×30**: подтверждённого официального API resize PTY в SDK 1.4.0 нет. Успешный login tty1 не доказывает готовность Xorg; ввод в tty1 при активном GUI требует отдельной проверки.

## Необязательная ручная настройка floating в конфиге i3

Для текущей сессии сначала рассмотрите [явную кнопку плавающего режима](#плавающий-режим-текущей-сессии): менять образ или оконный менеджер не требуется. Следующая ручная настройка — **другая, сохраняемая в overlay операция** для пользователя, которому нужно правило новых окон в конфиге. Launcher и кнопка сессионного режима её не выполняют автоматически; выключение сессионного режима не удаляет ваше ручное правило.

Сверено с [официальным руководством i3](https://i3wm.org/docs/userguide.html#_floating) и [upstream-конфигом, commit `810dc414`](https://github.com/leaningtech/alpine-image/blob/810dc414a8abfb3e21bf57b10651474baab39cdf/config/i3/config). [Dockerfile того же commit](https://github.com/leaningtech/alpine-image/blob/810dc414a8abfb3e21bf57b10651474baab39cdf/Dockerfile) копирует конфиг в **`/home/user/.config/i3/config`**. [Read-only инспекция настоящего гостя](../artifacts/desktop-optimization/guest-inspection.json) также подтверждает `set $mod Mod1`, `floating_modifier $mod`, bindings закрытия / floating и команды меню Apps. Это не проверка доставки каждого сочетания или drag в браузере. Ваш overlay мог уже изменить настройки; приоритет имеет фактически загруженный конфиг.

**Следующие команды — в терминале Linux внутри гостевого GUI, не в PowerShell.** Используйте терминал пользователя той же Xorg/i3-сессии, обычно `user`, а не root из другой tty.

1. Проверьте пользователя, домашний каталог и загруженный конфиг:

   ```sh
   whoami
   printf '%s\n' "$HOME"
   i3 --moreversion
   ```

   Ожидаемый upstream-путь — `/home/user/.config/i3/config`. i3 также поддерживает `~/.i3/config` и системный `/etc/i3/config`; не создавайте конкурирующий конфиг вслепую. Если загружен другой файл, используйте его фактический путь. Если main config системный, сначала разберитесь, как текущая сессия выбирает пользовательский конфиг; шаги ниже относятся к уже существующему пользовательскому файлу.

2. Для подтверждённого `~/.config/i3/config` сделайте резервную копию и запишите её имя:

   ```sh
   cfg="$HOME/.config/i3/config"
   backup="${cfg}.before-floating.$(date +%Y%m%d-%H%M%S)"
   cp -p "$cfg" "$backup"
   printf 'Backup: %s\n' "$backup"
   vi "$cfg"
   ```

3. Сохраните существующий `set $mod Mod1` (**Alt**, не Super / Windows). Вне блоков `mode` и других вложенных блоков добавьте правило для новых окон:

   ```i3
   for_window [class=".*"] floating enable
   ```

   Убедитесь, что уже существующая строка имеет вид `floating_modifier $mod`; в upstream она есть, повторно добавлять её не нужно. Правило относится к окнам с соответствующим X11 class; оно не гарантирует одинаковое поведение всех приложений, панелей и диалогов.

4. Проверьте синтаксис и перечитайте настройки из того же гостевого терминала:

   ```sh
   i3 -C -c "$cfg"
   i3-msg reload
   ```

   Если проверка сообщает ошибку, сначала исправьте её, не выполняйте reload. Новое правило — прежде всего для вновь появляющихся окон. Уже открытое окно переключайте вручную: фокус на нём → **Alt + Shift + Space**. Браузер / ОС могут перехватывать именно **Alt + Shift + Space**, поэтому это не гарантированный способ включить floating; правило выше позволяет включать его для новых подходящих окон без этого сочетания.

Для уже **плавающего** окна, с `floating_modifier $mod`: наведите мышь внутрь окна и удерживайте **Alt + левую кнопку** при перетаскивании для перемещения; **Alt + правую кнопку** — для изменения размера. Это [официальное поведение floating modifier](https://i3wm.org/docs/userguide.html#floating_modifier), не функция браузерной панели. Без Alt можно тянуть заголовок для перемещения и границы для размера. Полноэкранное окно i3 сначала верните через **Alt + F** — это не fullscreen браузера. В tiling перетаскивание меняет расположение контейнеров, а не превращает окно в свободно плавающее (`tiling_drag modifier titlebar` в проверенном конфиге).

### Вернуть tiling

Удалите добавленное `for_window` или восстановите записанную резервную копию. В том же терминале, если переменные ещё определены:

```sh
cp -p "$backup" "$cfg"
i3 -C -c "$cfg"
i3-msg reload
```

После новой терминальной сессии переменные нужно задать заново по сохранённым путям. Уже плавающие окна возвращаются в tiling через **Alt + Shift + Space**, если сочетание доходит до гостя. Сброс всего диска для этой настройки не нужен. Изменения конфигурации записываются в overlay асинхронно; `sync` не является подтверждённой гарантией мгновенного IDB commit.

## Основные сочетания

| Сочетание | Действие в upstream i3 |
| --- | --- |
| `Alt + Enter` / `Alt + D` | Терминал / rofi; доставка браузером не гарантируется |
| `Alt + Shift + Q` | Закрыть сфокусированное гостевое окно, не браузерную панель |
| `Alt + стрелки` / `Alt + Shift + стрелки` | Фокус / перемещение окна |
| `Alt + H` / `Alt + V` | Горизонтальное / вертикальное разбиение |
| `Alt + F` | Fullscreen окна i3 |
| `Alt + 1…9`, `Alt + 0` | Рабочие пространства 1…10 |
| `Alt + Shift + 1…9`, `Alt + Shift + 0` | Перенос окна на пространство |
| `Alt + Shift + Space` | Floating / tiling; браузер / ОС могут перехватить |
| `Alt + R` | Resize mode; `Enter` / `Escape` — выход |
| `Alt + Shift + C` | Перечитать конфиг |

Сначала закройте браузерную панель и щёлкните по гостевому экрану. Доставка сочетаний зависит от браузера / ОС и не гарантируется одной записью в конфиге. Используйте фактические bindings своего диска, если конфиг менялся. Ввод KMS обслуживает SDK; эти инструкции не добавляют synthetic keyboard / mouse или гарантированную вставку браузерного clipboard.

## Если нужен именно Openbox

Полная замена WM на Openbox — отдельная задача для совместимого custom image, а не изменение здесь. Новый base требует **нового `NEXT_PUBLIC_DISK_ID`**, даже если URL образа остался прежним; старый overlay повторно открывать на другом base нельзя. Потребуются проверка Xorg / пакетов / ввода и их лицензий, а также соблюдение proprietary-условий CheerpX. Автоматической миграции диска и подтверждённой совместимости Openbox здесь нет.
