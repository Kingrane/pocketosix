# Диск и необязательная сеть

[README](../README.ru.md) · [Архитектура](architecture.md) · [Разработка](development.md)

## Что сохраняется

Writable root — `OverlayDevice(base, IDBDevice)`; стандартный ID:

```text
pocketosix-alpine-20251007-v1
```

Сохраняются **файлы, установленные пакеты и настройки, уже записанные в browser storage**. RAM, процессы, открытые окна и терминальные сессии не сохраняются. Reload / закрытие заканчивает гостевую сессию; виртуальные `/proc`, `/sys`, `/dev` не хранят пользовательские файлы.

**Запись асинхронна.** В прежней диагностике гостевые `sync` и `cat` завершались до появления тестового файла в committed IDB-блоках: немедленный reload терял файл, после наблюдаемого commit файл переживал reload. Поддерживаемый durable-flush API CheerpX 1.4.0 не подтверждён; кнопки «Save» и гарантии мгновенного сохранения из этого не следует. Наблюдение одного committed маркера тоже не доказывает завершение всех очередей. [Исторический отчёт](../artifacts/redesign2/README.md).

Диск привязан к **профилю браузера и origin**: схема + хост + порт. `http://localhost:3000`, `http://127.0.0.1:3000`, другой порт, production-домен и preview URL — разные хранилища. Другой браузер / профиль также не видит этот диск. Приватный режим не подходит для длительного хранения. Очистка сайта удаляет локальные данные; квота, eviction и reset могут их уничтожить.

`navigator.storage.persist()` вызывается **по запросу пользователя**, может получить отказ и не защищает от ручного удаления. `navigator.storage.estimate()` показывает usage / quota **всего origin**, не точный размер гостевых файлов или base image. Разрешение persist снижает риск eviction, но не обещает бессрочную сохранность, offline или backup.

Writer удерживает эксклюзивный `navigator.locks` lock для диска весь срок записи. Перед новым boot закройте другую вкладку, которая уже владеет диском. Без безопасной блокировки запись не должна продолжаться молча. Cleanup, HMR и освобождение компонентов не означают сброс диска и не разрешают освобождать lock, пока старый runtime способен писать.

## Сброс и резервные копии

Reset выполняется **только после явного подтверждения потери файлов, пакетов и настроек**. Оболочка перезагружает документ, завершая старую VM; на новом preflight пользователь нажимает `> boot`, выбранный собственный overlay удаляется до запуска нового writer. Это не способ закрывать runtime и не автоматическое восстановление после ошибки. При blocked deletion нужно закрыть мешающую вкладку, а не очищать весь origin или чужие IDB-базы.

Полный безопасный export / import overlay через официальный SDK не реализован и не проверен. Экспорт всей VM, backup RAM, перенос полной работающей сессии также не поддерживаются. **Не храните здесь важные данные в единственном экземпляре.**

Base и overlay — неразрывная пара. Смена base **всегда требует нового overlay ID**, включая обновление содержимого по тому же URL. Никакой автоматической миграции нет. [Переменные custom image](development.md#конфигурация).

## Локальное исполнение — не offline

CheerpX loader получает proprietary runtime с официального CDN, base image стримится с внешнего сервера. Наличие writable IDB-overlay не означает, что весь base уже скачан или можно работать без интернета. Backend compute отсутствует, но CDN, хостинг веб-оболочки и опциональный Tailscale — реальные внешние зависимости.

## Tailscale

Гостевой GUI и локальные программы без сетевых запросов не требуют Tailscale или аккаунта. Подключение к tailnet — только действие пользователя, не часть boot.

Для публичного интернета гостя:

1. Откройте сетевую панель и начните подключение.
2. Войдите в свой Tailscale-аккаунт и подтвердите браузерное устройство.
3. Настройте и разрешите **свой внешний exit node** — Windows PC, Linux-машину или VPS. [Официальная инструкция](https://tailscale.com/kb/1408/quick-guide-exit-nodes).
4. Проверьте доступ **из гостя**, например `curl` / `wget`, если они установлены. `ping` не единственный критерий: низкоуровневые операции могут быть недоступны.

Tailscale IP сам по себе не доказывает интернет. Нужны доступный exit node, подходящие ACL / политика tailnet и реальная проверка запроса. PocketOSix не предоставляет общий exit node, публичный authkey или автоматический логин. Подключение может открыть гостю доступ к вашей частной сети — подключайте только доверенное окружение.

**Не помещайте auth keys, токены и пароли в код, `.env`, публичные URL, логи или репозиторий.** `NEXT_PUBLIC_*` публичны и не являются secret storage. Реальный Tailscale / exit node не проверялся в историческом REDESIGN2; новая документация не утверждает обратное.
